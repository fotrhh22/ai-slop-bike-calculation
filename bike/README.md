# 자전거 발전 측정소

Mac이 FNB58에서 USB HID 또는 BLE 측정값을 받고, iPad Safari가 Mac의 웹 화면에 접속하는 독립 측정 프로그램입니다. 기존 AI 챌린지 서버·Supabase·Render 배포와 별도로 실행합니다. iOS 앱, Web Bluetooth, 외부 CDN, 인터넷 연결은 필요하지 않습니다. 같은 Wi-Fi 안에서 Mac과 iPad가 서로 접속할 수 있어야 합니다.

## 실행

Python 3.9 이상이 필요합니다. 프로젝트 루트에서 전용 가상환경을 만듭니다.

```sh
python3 -m venv bike/.venv
source bike/.venv/bin/activate
python -m pip install -r bike/requirements.txt
python -m bike --host 0.0.0.0 --port 8765
```

- Mac: `http://127.0.0.1:8765`
- Mac의 Wi-Fi IP 확인: 시스템 설정 → Wi-Fi → 연결된 네트워크 세부사항 → TCP/IP. 일반적인 Wi-Fi 인터페이스에서는 `ipconfig getifaddr en0`으로도 확인할 수 있습니다.
- iPad: `http://<Mac의 Wi-Fi IP>:8765`. `localhost`나 `127.0.0.1`은 iPad 자신을 가리키므로 사용하지 않습니다.
- Mac 방화벽의 Python 연결 허용, Mac 절전 해제, 동일 Wi-Fi 및 기기 간 통신 허용이 필요합니다. 공용 게스트 Wi-Fi의 AP isolation이 켜져 있으면 접속할 수 없습니다.
- 이 서비스는 현장 LAN용이며 로그인 기능이 없습니다. 주소에 접속 가능한 기기는 측정을 조작할 수 있습니다. 신뢰하는 네트워크에서만 실행하고 포트 포워딩·인터넷 공개 배포는 하지 않습니다. 서로 다른 출처의 웹페이지가 조작하는 요청은 차단합니다.
- 기본 실행 `python -m bike`는 Mac에서만 열리는 `127.0.0.1`을 사용합니다. iPad 운영 때만 `--host 0.0.0.0`을 지정합니다.

## 장비 없이 먼저 확인

1. 웹 화면 하단의 **시뮬레이션**을 선택합니다.
2. 테스트 데이터 수신 표시를 확인하고 참가자 번호를 입력합니다.
3. **3분 측정 시작**을 누르면 0mWh부터 누적됩니다.
4. iPad와 Mac에서 동시에 같은 화면을 열거나 새로고침해도 같은 세션을 표시합니다.
5. 180초에 자동 종료하며, 수동 종료도 가능합니다.
6. 최근 기록에서 결과·샘플 CSV를 받습니다. **새 참가자**는 화면만 비우며 이전 기록을 삭제하지 않습니다.

시뮬레이션은 실제 발전량이 아니며 화면과 DB·CSV 모두 `demo`로 구분합니다. 실측 모드에서 연결이 끊겼다고 테스트 데이터로 대체하지 않습니다. 모드를 변경하면 현재 완료 화면이 비워지지만 이전 기록은 남습니다.

## FNB58 연결

```text
VOLT1-CD → USB-A 연장선 → FNB58 USB-A IN → USB-A OUT → 조절형 전자부하
                               ↑
                     전용 PC Micro-USB 보조 전원

FNB58 전용 PC 포트 ↔ USB 데이터 케이블 ↔ Mac 측정소 → Wi-Fi → iPad Safari
FNB58 → BLE → Mac 측정소 (USB와 별개 연결, 비교 가능)
```

1. 전자부하는 최저 전류 0.15A부터 시험합니다. 고속충전 트리거·전압 변경 기능은 사용하지 않습니다.
2. 보조 전원은 **전용 PC 포트**에만 연결합니다. 발전 입력을 빼고도 전자부하에 유의미한 전력이 흐르는지 먼저 확인합니다. 외부 전원 혼입이 의심되면 사용을 멈추고 연결을 확인합니다.
3. FNB58 메뉴에서 Bluetooth를 켭니다. 다른 앱(OpenFNB58, 브라우저 BLE 모니터, 휴대폰 앱)의 연결은 종료합니다.
4. 화면에서 **실측 · BLE → BLE 검색 → 기기 선택 → 연결**을 누릅니다. iPad에서 누르더라도 검색과 연결은 Mac에서 수행됩니다.
5. 최초 macOS Bluetooth 접근 권한 요청을 허용합니다. 필요하면 시스템 설정 → 개인정보 보호 및 보안 → Bluetooth에서 실행한 터미널 앱을 허용합니다.
6. **실측 수신 중**과 V/A/W를 확인한 뒤 시작합니다. 연결만 되고 측정 패킷이 오지 않으면 시작할 수 없습니다.

BLE 구현은 공개된 TLV 규격을 기반으로 합니다. `ffe4` 알림과 `ffe9` 쓰기 특성, 초기화 명령, CRC16-XMODEM 하위 1바이트 체크섬을 사용합니다. `0x04` 고정밀 V/I와 `0x07` 저정밀 V/I를 처리합니다. 고속충전 트리거, 장치 누적 그룹 초기화는 구현하지 않습니다. 펌웨어별 차이와 실제 구매 장비의 동작은 도착 후 검증해야 합니다.

## USB 유선 수신 및 USB·BLE 동시 비교

1. Mac과 FNB58 **전용 PC Micro-USB 포트**를 데이터 지원 케이블로 연결합니다. Mac 포트에 따라 USB 어댑터가 필요할 수 있습니다. 발전 입력·전자부하 연결은 그대로 둡니다.
2. 아래 명령으로 의존성을 업데이트하고 기존 서버를 종료한 뒤 다시 실행합니다. 같은 포트로 두 서버를 실행하지 않습니다.

   ```sh
   python -m pip install -r bike/requirements.txt
   python -m bike --host 0.0.0.0 --port 8765
   ```

3. 화면에서 **실측 · USB 유선**을 선택하고 **USB 검색 → 기기 선택 → 연결**을 누릅니다. USB는 `hidapi` 패키지의 `hid` 모듈을 사용합니다. 별도 `hid` 패키지나 pyserial, libusb 수신 코드가 아닙니다.
4. 실측 V/A/W와 패킷·유효 샘플 증가를 확인한 뒤 참가자 측정을 시작합니다. 연결만 되고 샘플이 오지 않으면 시작할 수 없습니다.
5. 비교하려면 USB를 연결해 둔 채 아래 BLE 영역에서 **BLE 검색 → 연결**합니다. 두 영역의 현재 V/A/W, 마지막 수신 경과, 패킷 수, 형식 오류 수를 나란히 확인합니다. 두 영역은 같은 시각에 채집한 값이 아니므로 순간 차이가 곧 계측 오차를 뜻하지 않습니다.
6. **참가자 누적은 위 모드 버튼에서 선택한 한쪽만 사용**합니다. 다른 쪽은 비교 전용입니다. 자동 대체·합산은 하지 않습니다. 모드를 바꾸려면 측정을 종료해야 하며, 변경 후 새 샘플이 와야 시작됩니다. 연결은 유지됩니다. 기록·CSV의 `mode`는 `usb` / `ble` / `demo`로 구분됩니다.
7. 주 통신이 끊겨도 타이머는 계속 가고 누락은 적분하지 않습니다. 같은 기기를 다시 검색·연결할 수 있습니다. 비교용 통신은 참가자 기록에 영향을 주지 않습니다. 화면에서 수동 연결 해제는 측정을 종료한 뒤 가능합니다.

**앱은 두 연결을 동시에 유지하도록 구현했지만, 구매한 FNB58 펌웨어가 USB·BLE 스트림을 동시에 계속 전송하는지는 실물 확인 전입니다.** 한쪽 초기화가 다른 쪽 전송을 멈추면 하나씩 연결해 순차 비교하세요. 다른 FNB58 모니터 앱은 종료한 상태로 시험합니다.

`usb_receiver.py`는 VID `2e3c`, PID `5558`인 HID 인터페이스만 검색합니다. HID 경로는 서버에만 보관하고 화면에는 불투명 ID를 전달합니다. 64바이트 명령에 0번 report ID를 붙여 65바이트로 쓰고, `81 → 82 → 82` 초기화 뒤 약 0.9초마다 `83` 요청을 보냅니다. 읽기는 200ms 제한을 가진 별도 스레드에서 수행하며 SQLite와 세션 변경은 이벤트 루프로 넘깁니다. 연결 해제는 읽기 종료 후 핸들을 닫습니다.

USB `AA 04` 64바이트 리포트에서 첫 번째 15바이트 샘플의 전압·전류를 little-endian uint32 / 100000으로 해석합니다. OpenFNB58처럼 **리포트당 첫 샘플 하나만 사용**합니다. 네 샘플의 정확한 장치 시각을 확인하지 못했으므로 임의로 시간 간격을 만들어 누적하지 않습니다. USB는 BLE TLV 디코더나 BLE 체크섬을 재사용하지 않습니다. 참고 USB 수신기와 마찬가지로 데이터 리포트 체크섬 검증은 아직 없으며 길이·헤더·5V 체험 범위 검증을 적용합니다. 수신 시각 기준의 근사 적분이므로 장치 누적 Wh와 완전히 같다고 보장하지 않습니다.

USB 검색이 비면 전용 PC 포트, 충전 전용 여부, USB 허브를 먼저 확인합니다. 연결 오류 또는 패킷이 계속 없으면 다른 PC 소프트웨어를 종료하고 케이블 재연결 후 검색하세요. macOS에서는 `hidapi`가 IOHIDManager를 사용하므로 libusb 커널 드라이버 분리 작업은 하지 않습니다.

## 측정 정의와 끊김 처리

- 표시값은 **USB 출력 경로에서 전력계가 측정한 전달 전력량**입니다. 사람의 기계적 출력, 발전기 내부 손실, 발전기의 잠재 최대 출력은 포함하지 않습니다. 전력계 자체 소비와 케이블 손실 등 장비 특성의 영향은 실물 비교가 필요합니다.
- `P = V × I`, `Wh += (P이전 + P현재) / 2 × Δt / 3600`의 사다리꼴 적분을 Mac에서 수행합니다. mWh는 Wh의 1000배입니다.
- 서버의 단조 증가 시계로 180초를 잽니다. iPad의 시계나 화면 갱신 횟수를 계산에 사용하지 않습니다.
- 시작 이전 샘플은 누적하지 않습니다. 첫 시작 이후 샘플부터 인접한 샘플 사이를 계산하며, 시작·끝의 미수신 부분은 추정하지 않습니다.
- 마지막 유효 샘플이 2초보다 오래되면 지연으로 표시합니다. 샘플 간격이 2초를 넘으면 그 구간은 적분하지 않습니다. USB·BLE 해제·재연결을 가로질러 적분하지 않습니다. 따라서 통신 누락이 있는 결과는 실제 전달량보다 적게 기록될 수 있습니다.
- 연결이 끊겨도 3분 타이머는 계속 진행합니다. 재연결되면 이후 실제 수신 구간만 집계합니다. 누락을 숨기지 않도록 **계측 구간 비율**을 보여줍니다. 이 값이 낮은 세션은 참가자 간 비교에 사용하지 않는 것이 좋습니다.
- 캠페인용 5V USB 경로 기준으로 0~6V, 0~1A의 유한한 값만 받습니다. 범위 밖 데이터는 누적하지 않고 경고합니다. 범위 변경 전에 실제 부하·전원·펌웨어 해석을 확인합니다.
- 전자부하의 고정 전류 설정과 USB 전압 안정화 때문에, 일정 속도 이상에서는 더 세게 밟아도 W가 비슷할 수 있습니다. 이 프로그램이 발전기의 최대 전력을 자동 추적하는 것은 아닙니다.
- AI 목표 Wh는 선택 입력입니다. 현재 AI 챌린지 서버와 자동 연동하지 않습니다. 검증된 실측 또는 명시된 추정값만 입력하고 임의의 소비량을 만들지 않습니다.

## 저장

`bike/data/station.sqlite3`에 참가자 결과와 시작 이후 샘플을 저장합니다. 프로그램 재시작 시 진행 중이던 세션은 `interrupted`로 표시하고 마지막 저장값을 보존합니다. **프로그램이 꺼진 동안의 전력량은 복구할 수 없습니다.** 종료된 결과의 평균 W는 전체 경과 시간 기준이며 누락이 있으면 낮아질 수 있습니다.

저장 위치는 `BIKE_DB_PATH` 환경변수로 바꿀 수 있습니다. 백업할 때는 프로그램을 정상 종료한 후 DB 파일을 복사하세요. 실행 중 복사하려면 SQLite 백업 기능을 사용해야 합니다. CSV는 한국어 이름을 보존하는 UTF-8 BOM을 포함하고 스프레드시트 수식으로 해석될 수 있는 참가자 이름을 이스케이프합니다. 시각은 DB에 UTC, 화면에는 한국 시간으로 표시합니다.

## 검증

```sh
python -m pip install -r bike/requirements-dev.txt
python -m unittest discover -s bike/tests -v
```
